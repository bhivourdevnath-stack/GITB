About the project

Discover browser games.

GITB — Games in the browser — is a curated directory that helps people find individual browser games and websites that offer browser games. It is designed to make discovery simple, fast, and useful without turning into a gaming platform.

What GITB does

Browse games by category, filter between games and websites, and search names, descriptions, categories, domains, and tags. GITB links directly to third-party game providers, so visitors can leave the directory and play on the original website.

GITB does not host game files, embed game players, require accounts, or collect player favorites. The catalog is stored in public JSON files and maintained through GitHub.

How the catalog works

Every listed resource has a stable identifier, name, public URL, resource type, category, tags, description, featured state, and curation status. The directory organizes resources using categories such as action, arcade, puzzle, strategy, racing, sports, and multiplayer.

Descriptions are kept short and factual. Resources marked as unverified have not yet been fully confirmed by a maintainer, while active resources are included in the catalog as currently intended listings.

How to contribute

Anyone can help improve GITB through GitHub. You do not need to know Flask, HTML, or JSON to suggest a resource or report a broken link.

  1. Search the directory and existing GitHub issues to check for duplicates.
  2. Open the resource suggestion form.
  3. Provide the game or website name, canonical public URL, type, best category, and a short useful description.
  4. Submit the issue and wait for a maintainer to review it.

To report a link that is unavailable, unsafe, or no longer correct, use the broken-link report form.

For technical contributors

Fork the repository, create a focused branch, and edit the catalog JSON files or other project source files. Games belong in data/games.json, while game-provider websites belong in data/websites.json. Category definitions live in data/categories.json.

  1. Use a stable, unique ID that does not exist in either catalog file.
  2. Use the original or canonical HTTP or HTTPS URL.
  3. Choose the category that best fits the resource.
  4. Write a neutral description based on the actual resource.
  5. Run the automated tests with python -m pytest.
  6. Open a pull request and explain the change clearly.

Submitting an issue does not automatically change the live directory. All additions and edits are reviewed before merging.

What submissions are reviewed for

  • Valid links: public URLs using HTTP or HTTPS and no deceptive redirects.
  • Duplicates: the same game or website should not be submitted more than once.
  • Category fit: the resource should belong in its selected category.
  • Useful descriptions: summaries should be concise, accurate, and neutral.
  • Safety: malware, credential theft, harmful downloads, scams, and deceptive pages are not appropriate.
  • Scope: suggestions should be browser-playable games or legitimate providers of browser games.

Privacy and external links

GITB does not operate the websites linked from the directory. External sites are independent services with their own availability, privacy policies, content, accounts, cookies, and rules.

Do not submit passwords, private information, account tokens, copyrighted files, or proprietary content. Only share publicly available information about a resource.

Project and license

GITB is built with Flask, HTML, CSS, and vanilla JavaScript. It uses JSON files instead of a database and keeps the project lightweight and easy to maintain.
